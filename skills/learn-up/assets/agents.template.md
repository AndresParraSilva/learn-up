## 1. Purpose & scope guardrail

`learn-up` is a local, single-user study app. One repo hosts **multiple independent topics**; the
home page is a topic picker. Every lesson, question, and lab MUST be tagged with a `domain` +
`objective` from its topic's `content/<topic_slug>/syllabus.yaml`. Do not add off-syllabus content.

**Every lesson body's first line is the Gemini Notebook video placeholder** — do not remove it until a
real `.mp4` link replaces it. Resolving a placeholder is user-paced and per-lesson (never bulk —
Gemini Notebook's free tier caps video generation to a handful a day), via one of: the lesson page's
"Generate Gemini Notebook video" button, the active coding agent driving the `notebooklm-mcp-cli` MCP server live on request, the
terminal script `scripts/generate_lesson_video.py`, or fully manual — the button and the script
both call `app/services/lesson_video.py` (needs `uv sync --group notebooklm` +
`uv run notebooklm login`). All four land the file at `media/<topic_slug>/<slug>.mp4`, served at
`/media/<topic_slug>/<slug>.mp4` (see README's "Generating lesson videos"). Every syllabus declares
`content_language` for authored material and an exact `notebooklm_output_language` locale code.
Before a new video request, the service validates that code with `notebooklm language list`, sets
the account-wide NotebookLM artifact language, and leaves language wording out of the prompt.

**Overall readiness** blends domain mastery (weighted by domain `weight_pct`), labs completion, and
strategy lessons-read, per the weight constants in `app/constants.py`. Disabled modules
redistribute their weight to domain mastery. `READY_THRESHOLD_PCT` plus a passed mock (for exam
topics) yields "GO".

## 2. Stack

- **Language/runtime:** Python **3.12+**, managed with **`uv`**.
- **Backend:** FastAPI (sync path ops) serving a JSON API; uvicorn for dev.
- **ORM/DB:** SQLAlchemy 2.x (**synchronous**) + **`duckdb_engine`**. Embedded **DuckDB** file
  `learn_up.duckdb`; all tables in schema **`learn`**. No async, no Alembic (schema via
  `Base.metadata.create_all`).
- **Config:** pydantic-settings; read config from the environment, never hardcode. Every setting
  must have a working default — `.env` is optional, and `.env.example` documents the full surface.
- **FAQ LLM:** three interchangeable backends under `app/services/lesson_qa/backends/`, selected by
  `LEARNUP_LLM_BACKEND`: `claude_cli` (shells out to `claude -p`, zero app-specific config),
  `codex_cli` (shells out to ephemeral, read-only `codex exec`, reusing the user's Codex login),
  and `openhands` (**optional** dep group, `uv sync --group openhands`; LiteLLM, any hosted or local
  provider). The default is `<faq_llm_backend>`, selected during intake. Prompting and parsing live in `lesson_qa/__init__.py` and must stay backend-agnostic;
  a new backend is one module exposing `name` / `check_available()` / `stream()`. Never add
  auto-detection or cross-backend fallback — the configured backend either runs or raises.
- **Content:** version-controlled **YAML/Markdown** under `content/<topic_slug>/`, seeded into DuckDB.
- **Frontend:** **React SPA** — Vite + **TypeScript** under `frontend/`.
- **Testing:** `pytest` (backend). `vitest` + `jsdom` (frontend) — used for content-validation
  checks (e.g. every `content/**/*.md` mermaid block must parse) as well as component/unit tests.
  Add deps only with `uv add` (backend) / the frontend package manager (frontend). Don't introduce a
  new framework or datastore without updating this file first.

## 3. Repository structure

```
/            pyproject.toml, .python-version, README.md, AGENTS.md, learn_up.duckdb (gitignored)
app/         FastAPI backend (api, services, content loader/validator, models, db, config)

sources/     downloaded study sources per topic (fed to Gemini Notebook) + INTAKE.md + SOURCES.md
media/       generated lesson videos, `<topic_slug>/<slug>.mp4` (gitignored), served at /media

             (also used by the lesson page's "Generate Gemini Notebook video" button; optional `notebooklm` dep group)
frontend/    React + Vite + TS SPA
tests/       backend tests
```

Keep `main.py` importing `app.main:app`.

## 4. Coding standards

- **Fail loudly on unexpected input.** Raise on missing/malformed content, unknown enum values, bad
  types. The content **validator** must error on any objective missing lessons/questions and on any
  dangling objective/topic tag. No silent defaults.
- **DuckDB is synchronous.** No async DB code. One uvicorn worker (single writer).
- Type-annotate Python; TypeScript strict on the frontend.
- Do not add unnecessary comments or inline documentation.
- Enums stored as strings, validated in Python against `StrEnum`.

## 5. Content-correctness rules

- Encode assessment facts as constants/config, not scattered magic numbers.
- The mock's question mix follows the domain `weight_pct` split in `syllabus.yaml`.
- Multi-select questions score all-or-nothing (selected set == correct set).
- Content carries a `syllabus_version` stamp and a `CHANGELOG.md`.
- **Labs store no credentials** — guided self-check only.

## 6. Commands

- Install/sync backend: `uv sync` · Add dep: `uv add <pkg>`
- Run backend (dev): `uv run uvicorn app.main:app --reload --port 8011`
- Seed content: `uv run python -m app.content.seed`
- Validate coverage: `uv run python -m app.content.validate`
- Tests: `uv run pytest`
- Frontend (from `frontend/`): `npm install`, `npm run dev`, `npm run build`, `npm run lint`,
  `npm test` (vitest)
